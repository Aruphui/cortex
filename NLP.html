🧹 Text Preprocessing — Cleaning Before Anything Else

Imagine you want to count words in a book, but the book is full of typos, HTML tags, weird symbols, and inconsistent capitalization. Preprocessing is the act of cleaning all that mess up so algorithms can work properly.

🧠 Why it matters

"Hello!" and "hello" and "HELLO" — are these the same word? To a naive algorithm, NO. After normalization, they all become "hello". This dramatically improves model accuracy.

Traditional Code — Python

# Install: pip install nltk re
import re
import nltk
nltk.download('punkt')
nltk.download('wordnet')

from nltk.tokenize import word_tokenize
from nltk.stem import WordNetLemmatizer, PorterStemmer

text = "Hello! Visit https://azure.com for <b>Azure AI</b> Services. Running 3 models..."

# Step 1: Remove HTML tags
text = re.sub(r'<.*?>', '', text)

# Step 2: Remove URLs
text = re.sub(r'http\S+', '', text)

# Step 3: Lowercase
text = text.lower()

# Step 4: Remove special characters
text = re.sub(r'[^a-z\s]', '', text)

# Step 5: Tokenize
tokens = word_tokenize(text)

# Step 6: Stem (aggressive, fast)
stemmer = PorterStemmer()
stemmed = [stemmer.stem(t) for t in tokens]
print("Stemmed:", stemmed)
# ['hello', 'azur', 'ai', 'servic', 'run', 'model']

# Step 7: Lemmatize (smarter, uses dictionary)
lemmatizer = WordNetLemmatizer()
lemmatized = [lemmatizer.lemmatize(t) for t in tokens]
print("Lemmatized:", lemmatized)
# ['hello', 'azure', 'ai', 'service', 'running', 'model']
✅ Stem vs Lemmatize — Simple Rule

Stemming chops the end off words blindly → "running" → "run", "better" → "better" (wrong!)
Lemmatization uses a dictionary → "better" → "good" ✓, "running" → "run" ✓
Use lemmatization unless speed is critical.

⚠️ When NOT to preprocess heavily

For modern LLMs (GPT-4, BERT), don't lowercase or stem! These models understand context and capitalization is useful signal. Heavy preprocessing actually hurts transformer performance.

🛑 Stop Words & Text Normalization

Stop words are very common words that carry little meaning on their own — "the", "is", "a", "and", "in". Removing them reduces noise and speeds up processing for classical ML models.

❌ Before Stop Word Removal
  • "The quick brown fox jumped over the lazy dog"
  • 12 words — many carry no meaning for classification
✅ After Stop Word Removal
  • "quick brown fox jumped lazy dog"
  • 6 words — all meaningful content words
from nltk.corpus import stopwords
nltk.download('stopwords')

stop_words = set(stopwords.words('english'))
tokens = ["the", "quick", "brown", "fox", "is", "amazing"]

filtered = [w for w in tokens if w not in stop_words]
print(filtered)  # ['quick', 'brown', 'fox', 'amazing']

# Custom stop words for domain-specific use
custom_stops = stop_words | {"azure", "microsoft", "please"}
filtered_custom = [w for w in tokens if w not in custom_stops]

🎒 Bag of Words (BoW) & TF-IDF

Machine learning algorithms can't understand text — they only understand numbers. BoW and TF-IDF are methods to convert text into numbers.

Bag of Words — The "Dumb" but Useful Method

🧠 Simple Explanation

Imagine you have a bag. You throw all words from a document into that bag. You don't care about order, grammar, or meaning. You just count: how many times did each word appear? That count-vector IS the Bag of Words.

from sklearn.feature_extraction.text import CountVectorizer

docs = [
    "I love Azure AI",
    "Azure AI is amazing",
    "I love machine learning"
]

vectorizer = CountVectorizer()
X = vectorizer.fit_transform(docs)

print(vectorizer.vocabulary_)
# {'i':2, 'love':4, 'azure':1, 'ai':0, 'is':3, 'amazing':..., 'machine':..., 'learning':...}

print(X.toarray())
# Doc1: [1, 1, 1, 0, 1, 0, 0, 0]  ← has azure, ai, i, love
# Doc2: [1, 1, 0, 1, 0, 1, 0, 0]  ← has azure, ai, is, amazing
# Doc3: [0, 0, 1, 0, 1, 0, 1, 1]  ← has i, love, machine, learning
⚠️ BoW Limitations

❌ "I love NLP" and "NLP love I" produce identical BoW vectors (word order lost)
❌ Common words like "the" dominate even if meaningless
❌ Vocabulary grows huge with large datasets (sparse matrix problem)
✅ TF-IDF fixes some of these issues!

TF-IDF — Smarter Word Weighting

TF-IDF = Term Frequency × Inverse Document Frequency
Idea: A word is important if it appears often in THIS document BUT rarely across ALL documents.

TF (Term Frequency)
  • How often does word appear in THIS document?
  • "azure" appears 3 times in 100-word doc = TF = 0.03
  • More occurrences → higher TF
IDF (Inverse Document Frequency)
  • How rare is the word across ALL documents?
  • "the" appears in every doc → very low IDF
  • "Kubernetes" appears in few docs → very high IDF
from sklearn.feature_extraction.text import TfidfVectorizer

docs = [
    "Azure AI is amazing for NLP tasks",
    "NLP tasks include sentiment analysis and NER",
    "Sentiment analysis is important in business"
]

tfidf = TfidfVectorizer(max_features=10)
X = tfidf.fit_transform(docs)

print("Feature names:", tfidf.get_feature_names_out())
print("TF-IDF matrix shape:", X.shape)  # (3, 10)

# Words that appear in ALL documents get low score ("is", "in")
# Domain-specific words get high score ("azure", "ner", "kubernetes")

🔗 N-Grams — Capturing Word Sequences

BoW treats every word independently. But "not good" means something very different from "good". N-grams capture consecutive word sequences, adding a sense of order and phrase context.

📖 N-gram Types
  • Unigram (n=1): ["I", "love", "NLP"] — individual words
  • Bigram (n=2): ["I love", "love NLP"] — pairs of words
  • Trigram (n=3): ["I love NLP"] — triples of words
  • Character n-grams: work on characters, great for misspellings
from sklearn.feature_extraction.text import CountVectorizer
from nltk.util import ngrams
from nltk.tokenize import word_tokenize

# Manual bigrams
text = "not good product not recommended"
tokens = word_tokenize(text)
bigrams = list(ngrams(tokens, 2))
print(bigrams)
# [('not', 'good'), ('good', 'product'), ('product', 'not'), ('not', 'recommended')]
# 'not good' is captured as a unit — BoW would have missed this!

# Use n-grams in sklearn pipeline
vectorizer = CountVectorizer(ngram_range=(1, 2))  # unigrams + bigrams
docs = ["not good", "very good", "not bad"]
X = vectorizer.fit_transform(docs)
print(vectorizer.get_feature_names_out())
# ['bad', 'good', 'not', 'not bad', 'not good', 'very', 'very good']
# Now 'not good' and 'very good' are DIFFERENT features!
✅ When to Use N-Grams
  • Sentiment analysis (negation: "not good", "not happy")
  • Spam detection ("click here", "limited time", "act now")
  • Language modeling and text generation (traditional)
  • Character n-grams for spell correction and author identification

🤖 Traditional Machine Learning for NLP

Once you have your text as numbers (via BoW or TF-IDF), you can feed them into classic ML classifiers. These are fast, interpretable, and surprisingly effective.

Naive Bayes — The Probability Classifier

🧠 How Naive Bayes Works (Simple!)

It calculates: "Given these words in the email, what's the probability it's spam?" It's "naive" because it assumes all words are independent (which isn't quite true, but it works great anyway!)
Training: count word frequencies in spam vs non-spam emails. Prediction: multiply probabilities → "free money winner" → 95% spam.

from sklearn.naive_bayes import MultinomialNB
from sklearn.feature_extraction.text import TfidfVectorizer
from sklearn.pipeline import Pipeline
from sklearn.model_selection import train_test_split
from sklearn.metrics import classification_report

# Sample dataset
texts = [
    "Win free money now click here",          # spam
    "Limited offer buy now discount",          # spam
    "Meeting at 3pm in conference room",        # ham
    "Please review the attached report",        # ham
    "Congratulations you won a prize",          # spam
    "Can you join the call tomorrow morning",   # ham
]
labels = [1, 1, 0, 0, 1, 0]  # 1=spam, 0=ham

X_train, X_test, y_train, y_test = train_test_split(
    texts, labels, test_size=0.3, random_state=42)

# Pipeline: TF-IDF → Naive Bayes
model = Pipeline([
    ('tfidf', TfidfVectorizer()),
    ('clf',  MultinomialNB())
])
model.fit(X_train, y_train)
predictions = model.predict(X_test)
print(classification_report(y_test, predictions))

Logistic Regression for Text

from sklearn.linear_model import LogisticRegression

model = Pipeline([
    ('tfidf', TfidfVectorizer(ngram_range=(1,2), max_features=5000)),
    ('clf',  LogisticRegression(max_iter=1000))
])
model.fit(X_train, y_train)

# Logistic Regression is great for text — often beats Naive Bayes
# Works well even with limited data
# You can see which words are most important for each class:
feature_names = model.named_steps['tfidf'].get_feature_names_out()
coefs = model.named_steps['clf'].coef_[0]
top_spam = feature_names[coefs.argsort()[-5:]]
print("Top spam words:", top_spam)

Support Vector Machine (SVM) for Text

from sklearn.svm import LinearSVC

# SVM is often the BEST classical classifier for text
# It finds the optimal boundary between classes in high-dimensional space
model = Pipeline([
    ('tfidf', TfidfVectorizer(max_features=10000)),
    ('clf',  LinearSVC(C=1.0))
])
model.fit(X_train, y_train)
print("Accuracy:", model.score(X_test, y_test))

🔧 Feature Engineering for Text Data

Beyond word counts, you can engineer powerful features that capture more signal from text. This is the art of turning domain knowledge into model inputs.

Common Text Features

import pandas as pd
import re
from textblob import TextBlob   # pip install textblob

df = pd.DataFrame({'text': ["I LOVE Azure!!!", "meh product not great"]})

# Structural features
df['char_count']      = df['text'].apply(len)
df['word_count']      = df['text'].apply(lambda x: len(x.split()))
df['uppercase_ratio'] = df['text'].apply(lambda x: sum(1 for c in x if c.isupper())/len(x))
df['exclamation_ct']  = df['text'].apply(lambda x: x.count('!'))
df['question_marks']  = df['text'].apply(lambda x: x.count('?'))
df['avg_word_len']    = df['text'].apply(lambda x: sum(len(w) for w in x.split())/len(x.split()))

# Sentiment polarity as a feature (TextBlob)
df['polarity']     = df['text'].apply(lambda x: TextBlob(x).sentiment.polarity)
df['subjectivity'] = df['text'].apply(lambda x: TextBlob(x).sentiment.subjectivity)

print(df)

🧬 Neural Network Basics — How Machines Learn Patterns

A neural network is a system of interconnected layers of "neurons" — mathematical functions that transform input numbers into output numbers. Through training on examples, it automatically learns the right transformations.

🧠 Think of it like this

A neuron takes multiple inputs, multiplies each by a "weight" (importance), sums them up, and passes through an activation function.
Millions of these neurons, stacked in layers, can approximate any function — including "does this review have positive sentiment?"

Feed-Forward Network for Text Classification

import torch
import torch.nn as nn
from sklearn.feature_extraction.text import TfidfVectorizer

# Convert text to TF-IDF vectors, then pass through a neural network
class TextClassifierNN(nn.Module):
    def __init__(self, input_dim, hidden_dim, num_classes):
        super().__init__()
        self.network = nn.Sequential(
            nn.Linear(input_dim, hidden_dim),  # Input layer
            nn.ReLU(),                           # Activation — adds non-linearity
            nn.Dropout(0.3),                    # Prevent overfitting
            nn.Linear(hidden_dim, hidden_dim),  # Hidden layer
            nn.ReLU(),
            nn.Linear(hidden_dim, num_classes) # Output layer
        )
    def forward(self, x):
        return self.network(x)

# Training loop (simplified)
model = TextClassifierNN(input_dim=5000, hidden_dim=256, num_classes=2)
optimizer = torch.optim.Adam(model.parameters(), lr=1e-3)
criterion = nn.CrossEntropyLoss()

for epoch in range(10):
    optimizer.zero_grad()
    outputs = model(X_train_tensor)   # Forward pass
    loss = criterion(outputs, y_train_tensor)
    loss.backward()                    # Backpropagation
    optimizer.step()                   # Update weights

🔄 RNNs, LSTMs & GRUs — Sequential Memory

Text is a sequence — word order matters. "Dog bites man" ≠ "Man bites dog". Feed-forward networks ignore order. Recurrent Neural Networks (RNNs) process text word-by-word, maintaining a "hidden state" (memory) from previous words.

🧠 RNN Analogy

Imagine reading a sentence word by word. As you read each word, you update your understanding. "The movie was NOT..." — after reading "NOT", your understanding shifts completely. An RNN does the same: each word updates the hidden state (understanding so far).

⚠️ RNN Problem: Vanishing Gradients

In long sentences, RNNs "forget" information from early words by the time they reach the end. "The cat, which lived in a big house with many rooms and a garden, was hungry." By "hungry", RNN has forgotten "cat". LSTM and GRU solve this!

LSTM — Long Short-Term Memory

LSTM has three "gates" — like information checkpoints:

🚪

Forget Gate

Decides what to FORGET from memory. "We just changed topic, forget old context."

📥

Input Gate

Decides what NEW info to STORE. "This word is important, remember it!"

📤

Output Gate

Decides what to OUTPUT based on current state. "Given memory + input, output this."

import torch.nn as nn
import torch

class LSTMClassifier(nn.Module):
    def __init__(self, vocab_size, embed_dim, hidden_dim, num_classes):
        super().__init__()
        self.embedding = nn.Embedding(vocab_size, embed_dim)   # word → vector
        self.lstm      = nn.LSTM(embed_dim, hidden_dim,
                               batch_first=True, bidirectional=True)
        self.fc        = nn.Linear(hidden_dim*2, num_classes)  # *2 for bidirectional

    def forward(self, x):
        embedded = self.embedding(x)           # (batch, seq_len, embed_dim)
        output, (hidden, _) = self.lstm(embedded)
        # Take final hidden state (concat forward + backward)
        hidden_cat = torch.cat((hidden[-2], hidden[-1]), dim=1)
        return self.fc(hidden_cat)

GRU — Gated Recurrent Unit (Simpler LSTM)

# GRU has only 2 gates (vs 3 in LSTM) → faster, uses less memory
# Often performs similarly to LSTM — use GRU as default unless you need LSTM's expressiveness
self.gru = nn.GRU(input_size=128, hidden_size=256, 
                  num_layers=2, batch_first=True, dropout=0.3)

Problem: A single context vector is a bottleneck for long sentences → Attention mechanism solves this (covered in Phase 4).

🗺️ Word Embeddings — Meaning as Vectors

Instead of one-hot encoding (which treats every word as completely unrelated), word embeddings represent words as dense vectors in a high-dimensional space where similar words end up close together.

🧠 The Famous Equation

King − Man + Woman ≈ Queen
This means the direction from "man" to "woman" (gender direction) is the same as from "king" to "queen". Embeddings capture this mathematical structure of language!

Word2Vec — Predicting Context

Two training approaches:

CBOW (Continuous Bag of Words)
  • Input: surrounding words
  • Output: predict the middle word
  • "I __ Azure" → predict "love"
  • Faster, works better for frequent words
Skip-gram
  • Input: middle word
  • Output: predict surrounding words
  • "love" → predict ["I", "Azure"]
  • Slower, better for rare words
# Train Word2Vec with gensim
# pip install gensim
from gensim.models import Word2Vec

sentences = [
    ["i", "love", "azure", "ai"],
    ["azure", "openai", "is", "powerful"],
    ["nlp", "with", "transformers", "is", "amazing"],
    # ... thousands of sentences in practice
]

model = Word2Vec(
    sentences=sentences,
    vector_size=100,    # embedding dimensions
    window=5,           # context window size
    min_count=1,        # ignore words with fewer occurrences
    sg=1                 # 1=Skip-gram, 0=CBOW
)
model.save("word2vec.model")

# Find similar words
print(model.wv.most_similar("azure", topn=3))
# [('openai', 0.92), ('ai', 0.87), ('cloud', 0.85)]

import numpy as np

def load_glove(filepath):
    embeddings = {}
    with open(filepath, encoding='utf-8') as f:
        for line in f:
            parts = line.split()
            word = parts[0]
            vector = np.array(parts[1:], dtype='float32')
            embeddings[word] = vector
    return embeddings

👁️ Attention Mechanism — The Breakthrough Idea

The problem with RNNs: a single context vector can't capture all information from long sequences. The Attention Mechanism (2015) says: "Instead of a single vector, let the decoder look back at ALL encoder states and decide which parts are most relevant."

🧠 Attention — Simple Analogy

When translating "The animal didn't cross the street because it was too tired", the word "it" should attend (pay attention) to "animal" not "street".
Attention computes a weight for each previous word: how relevant is this word for generating my current output word? High weight = more relevant.

Self-Attention — The Transformer Core

Self-attention is attention applied within a sequence (each word attends to every other word). This captures relationships regardless of distance — "was" attends to "animal" even if they're 10 words apart.

For each word, self-attention creates 3 vectors: Query, Key, Value

import torch
import torch.nn as nn
import torch.nn.functional as F
import math

def scaled_dot_product_attention(Q, K, V, mask=None):
    """
    Q: Query  — "What am I looking for?"
    K: Key    — "What do I contain?"
    V: Value  — "What do I actually provide?"
    
    1. Multiply Q by K^T → attention scores (how relevant is each word?)
    2. Scale by sqrt(d_k) → prevent exploding gradients
    3. Softmax → convert to probabilities summing to 1
    4. Multiply by V → weighted sum of values
    """
    d_k = Q.size(-1)
    scores = torch.matmul(Q, K.transpose(-2, -1)) / math.sqrt(d_k)
    if mask is not None:
        scores = scores.masked_fill(mask == 0, -1e9)
    attn_weights = F.softmax(scores, dim=-1)
    return torch.matmul(attn_weights, V), attn_weights

Multi-Head Attention

Instead of one attention computation, run it h times in parallel with different learned projections. Each "head" learns to attend to different types of relationships (syntax, semantics, coreference, etc.). 

class MultiHeadAttention(nn.Module):
    def __init__(self, d_model=512, n_heads=8):
        super().__init__()
        self.n_heads = n_heads
        self.d_k = d_model // n_heads   # 512/8 = 64 per head

        self.W_Q = nn.Linear(d_model, d_model)  # Query projection
        self.W_K = nn.Linear(d_model, d_model)  # Key projection
        self.W_V = nn.Linear(d_model, d_model)  # Value projection
        self.W_O = nn.Linear(d_model, d_model)  # Output projection

    def forward(self, Q, K, V):
        batch = Q.size(0)
        # Project and split into heads
        Q = self.W_Q(Q).view(batch, -1, self.n_heads, self.d_k).transpose(1,2)
        K = self.W_K(K).view(batch, -1, self.n_heads, self.d_k).transpose(1,2)
        V = self.W_V(V).view(batch, -1, self.n_heads, self.d_k).transpose(1,2)
        # Attention for each head simultaneously (parallelized!)
        attn_output, _ = scaled_dot_product_attention(Q, K, V)
        # Concatenate heads and project
        attn_output = attn_output.transpose(1,2).contiguous().view(batch, -1, self.n_heads*self.d_k)
        return self.W_O(attn_output)
