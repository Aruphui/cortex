Core Python

📦 Data Types — list & dict Fundamental

🔷 What is a List?

A list is an ordered, mutable collection. You can store anything — strings, numbers, even other lists.

# Creating lists
fruits = ["apple", "banana", "cherry"]

# Indexing (0-based)
print(fruits[0])      # "apple"
print(fruits[-1])     # "cherry"  ← negative index = from end

# Slicing  [start : stop : step]
print(fruits[0:2])    # ["apple", "banana"]

# Common methods
fruits.append("mango")     # add to end
fruits.insert(1, "kiwi")  # insert at index 1
fruits.remove("banana")   # remove by value
fruits.pop()               # remove last item
len(fruits)                 # count items
sorted(fruits)              # returns new sorted list
fruits.sort()               # sorts in-place

# Check membership
if "apple" in fruits:
    print("found!")

# Nested list
matrix = [[1,2],[3,4]]
print(matrix[0][1])   # 2

🔷 What is a Dict? (Most Important for LLM work!)

A dictionary is an ordered (Python 3.7+), mutable key-value store. LLM APIs return JSON — which becomes a dict in Python.

# Creating a dict
person = {
    "name": "Arup",
    "age": 28,
    "skills": ["Python", "LLM"]
}

# Access values
print(person["name"])          # "Arup"  (KeyError if missing)
print(person.get("city", "N/A")) # "N/A"  (safe – no KeyError)

# Add / Update
person["city"] = "Kolkata"   # add new key
person["age"]  = 29           # update existing key

# Delete
del person["city"]
person.pop("age")

# Iterate
for key, value in person.items():
    print(key, "→", value)

for k in person.keys():   print(k)
for v in person.values(): print(v)

# Merge two dicts (Python 3.9+)
extra = {"role": "engineer"}
merged = person | extra

# Check key existence
if "name" in person:
    print("has name")

# Nested dict (very common in LLM API responses)
llm_response = {
    "id": "chatcmpl-abc",
    "choices": [
        {
            "message": {
                "role": "assistant",
                "content": "Hello! How can I help?"
            }
        }
    ]
}
# Drill into nested structure
text = llm_response["choices"][0]["message"]["content"]
print(text)  # "Hello! How can I help?"

🎯 Interview Q

Q: What's the difference between a list and a tuple?
A: Both are ordered sequences. A list is mutable (can change after creation) while a tuple is immutable. Use tuples when data should not change (e.g., coordinates, config constants).

🎯 Interview Q

Q: How do you safely access a nested key in a dict?
A: Use .get() chaining or handle KeyError with try/except. Example: data.get("choices", [{}])[0].get("message", {}).get("content")

⚡ List Comprehensions Pythonic

🔷 Syntax: [expression for item in iterable if condition]

# Traditional loop way
squares = []
for x in range(5):
    squares.append(x ** 2)

# List comprehension way (Pythonic ✅)
squares = [x ** 2 for x in range(5)]
# [0, 1, 4, 9, 16]

# With condition
evens = [x for x in range(10) if x % 2 == 0]
# [0, 2, 4, 6, 8]

# Extract data from list of dicts (LLM use case!)
messages = [
    {"role": "user",      "content": "Hi"},
    {"role": "assistant", "content": "Hello!"},
    {"role": "user",      "content": "How are you?"},
]
# Get only user messages
user_msgs = [m["content"] for m in messages if m["role"] == "user"]
# ["Hi", "How are you?"]

# Dict comprehension
token_counts = {m["role"]: len(m["content"].split()) for m in messages}
# {'user': 3, 'assistant': 1}  ← last value wins for duplicate keys

# Flatten nested list
nested = [[1,2],[3,4],[5]]
flat = [x for sub in nested for x in sub]
# [1, 2, 3, 4, 5]

🗂️ JSON Handling Critical for LLMs

🔷 The json Module

JSON (JavaScript Object Notation) is the language of APIs. Every LLM response is JSON.

import json

# ── JSON string → Python dict  (parsing / deserializing)
json_str = '{"model": "gpt-4o", "temperature": 0.7}'
data = json.loads(json_str)    # "loads" = load from String
print(type(data))             # <class 'dict'>
print(data["model"])         # "gpt-4o"

payload = {
    "messages": [{"role": "user", "content": "Hi"}],
    "model": "gpt-4o"
}
json_str = json.dumps(payload, indent=2)  # pretty print
print(json_str)

# ── Read JSON from a file
with open("config.json", "r") as f:
    config = json.load(f)     # "load" = load from File

# ── Write JSON to a file
with open("output.json", "w") as f:
    json.dump(payload, f, indent=2)

🎯 Interview Q

Q: What is the difference between json.loads() and json.load()?
A: json.loads() parses a JSON string into a Python object. json.load() reads from a file object. Same for json.dumps() (to string) vs json.dump() (to file).

OOP — Object Oriented Programming

🏛️ Classes Important

🔷 What is a Class?

A class is a blueprint. An instance/object is a concrete thing built from that blueprint. Think: Class = Cookie cutter, Object = Cookie.

class LLMClient:
    # Class variable (shared by ALL instances)
    provider = "OpenAI"

    # __init__ = constructor (called when you create an object)
    def __init__(self, api_key: str, model: str = "gpt-4o"):
        # Instance variables (unique to each object)
        self.api_key = api_key
        self.model   = model
        self.history = []        # each client has its own history

    # Instance method
    def chat(self, message: str) -> str:
        self.history.append({"role": "user", "content": message})
        # (In real code: call the actual API here)
        reply = f"Echo: {message}"
        self.history.append({"role": "assistant", "content": reply})
        return reply

    # Dunder method: how the object prints
    def __repr__(self) -> str:
        return f"LLMClient(model={self.model})"


# ── Creating instances
client1 = LLMClient("sk-abc123")
client2 = LLMClient("sk-xyz", model="gpt-3.5")

print(client1)           # LLMClient(model=gpt-4o)
print(client2.model)    # gpt-3.5
print(LLMClient.provider) # OpenAI

reply = client1.chat("What is LLM?")
print(client1.history)
ℹ️ self self is a reference to the current instance. It's always the first parameter of instance methods. Python passes it automatically — you never pass it manually.
🗃️ Dataclasses Modern Python

🔷 What is a Dataclass?

A dataclass auto-generates boilerplate (__init__, __repr__, __eq__) for classes that mainly hold data. Perfect for API request/response models.

from dataclasses import dataclass, field

@dataclass
class Message:
    role: str
    content: str

@dataclass
class ChatRequest:
    model: str = "gpt-4o"
    temperature: float = 0.7
    max_tokens: int = 512
    # field(default_factory=...) for mutable defaults (list, dict)
    messages: list[Message] = field(default_factory=list)

# Usage
req = ChatRequest()
req.messages.append(Message(role="user", content="Hello"))
print(req)
# ChatRequest(model='gpt-4o', temperature=0.7, ...)

🔷 Frozen Dataclasses (Immutable)

@dataclass(frozen=True)   # makes it immutable (like a tuple)
class ModelConfig:
    name: str
    max_context: int

cfg = ModelConfig("gpt-4o", 128000)
# cfg.name = "other"  ← raises FrozenInstanceError
🎯 Interview Q

Q: Why use dataclass instead of a regular class?
A: Dataclasses eliminate boilerplate. You don't need to write __init__, __repr__, or __eq__ manually. They're ideal for data-carrying classes. Pydantic models (used in FastAPI) are the next level up — they add runtime validation.

🧬 Inheritance Important

🔷 Single Inheritance — "is-a" relationship

class BaseLLMClient:
    def __init__(self, api_key: str):
        self.api_key = api_key

    def chat(self, prompt: str) -> str:
        raise NotImplementedError("Subclass must implement chat()")

    def validate_key(self):
        return self.api_key.startswith("sk-")


class OpenAIClient(BaseLLMClient):    # ← inherits BaseLLMClient
    def __init__(self, api_key: str, model: str = "gpt-4o"):
        super().__init__(api_key)     # call parent's __init__
        self.model = model

    def chat(self, prompt: str) -> str:   # ← overrides parent
        return f"[OpenAI {self.model}] {prompt}"


class AnthropicClient(BaseLLMClient):
    def chat(self, prompt: str) -> str:
        return f"[Claude] {prompt}"


# Usage
oai = OpenAIClient("sk-abc")
ant = AnthropicClient("sk-xyz")

print(oai.chat("Hi"))          # [OpenAI gpt-4o] Hi
print(oai.validate_key())   # True  (inherited from Base)

# Polymorphism — treat them all the same way
for client in [oai, ant]:
    print(client.chat("Hello"))
🎯 Interview Q

Q: What does super() do?
A: super() gives you access to the parent class's methods. It's used in __init__ to initialize the parent before adding child-specific stuff. Without super().__init__(), parent attributes won't be set up.

🔗 Composition Prefer over Inheritance

🔷 What is Composition? — "has-a" relationship

Instead of inheriting, you include another class as a field. "Prefer composition over inheritance" is a key OOP principle.

class TokenCounter:
    def __init__(self):
        self.total = 0

    def count(self, text: str) -> int:
        tokens = len(text.split())
        self.total += tokens
        return tokens


class MessageHistory:
    def __init__(self):
        self.messages: list[dict] = []

    def add(self, role: str, content: str):
        self.messages.append({"role": role, "content": content})

    def to_list(self) -> list[dict]:
        return self.messages


# ── Composition: ChatBot HAS-A TokenCounter and HAS-A MessageHistory
class ChatBot:
    def __init__(self):
        self.counter = TokenCounter()      # composed in
        self.history = MessageHistory()   # composed in

    def send(self, text: str):
        self.counter.count(text)
        self.history.add("user", text)
        print(f"Tokens so far: {self.counter.total}")

bot = ChatBot()
bot.send("What is the capital of France?")
bot.send("Tell me more about it")
print(bot.history.to_list())
ApproachWhen to useKey word
InheritanceStrict "is-a" — OpenAIClient is a BaseLLMClientclass Child(Parent)
Composition"has-a" — ChatBot has a MessageHistoryassign in __init__
🎯 Interview Q

Q: Composition vs Inheritance — when to choose which?
A: Use inheritance when there's a true "is-a" relationship and you want to share and override behavior. Use composition when you want flexibility — it avoids the tight coupling of inheritance and makes code easier to test and swap out.

Async Programming

⚡ async / await & asyncio LLM Essential

🔷 Why Async?

LLM API calls are I/O-bound (waiting for network). Async lets Python do other work while waiting, instead of sitting idle. This is how you handle 100 simultaneous requests instead of 1 at a time.

Sync (blocking)Async (non-blocking)
Task 1 → wait 2s → Task 2 → wait 2s → Done in 4sTask 1 starts, Task 2 starts, both finish → Done in 2s

🔷 async def and await

import asyncio

# async def defines a "coroutine" – a pausable function
async def fetch_response(query: str) -> str:
    print(f"Sending: {query}")
    # await = "pause here, let other code run while waiting"
    await asyncio.sleep(1)   # simulates a 1-second API call
    return f"Answer to: {query}"

async def main():
    # Run one at a time (still async, but sequential)
    r1 = await fetch_response("What is AI?")
    r2 = await fetch_response("What is LLM?")
    print(r1, r2)

# Run the async event loop
asyncio.run(main())

🔷 asyncio.gather — Run tasks CONCURRENTLY

async def main_concurrent():
    # gather runs ALL tasks at the same time → much faster!
    results = await asyncio.gather(
        fetch_response("What is AI?"),
        fetch_response("What is Python?"),
        fetch_response("Explain async"),
    )
    # results is a list in the same order as the calls
    for r in results:
        print(r)

asyncio.run(main_concurrent())
# All 3 run in parallel → finishes in ~1s instead of 3s

🔷 asyncio.create_task — Fire and forget / background tasks

async def main_task():
    # Create tasks that start running immediately in background
    task1 = asyncio.create_task(fetch_response("Q1"))
    task2 = asyncio.create_task(fetch_response("Q2"))

    # Do something else here...
    print("Tasks are running in background!")

    # Collect results
    r1 = await task1
    r2 = await task2
    print(r1, r2)
🚨 Common Mistake You CANNOT use await inside a normal (def) function — only inside async def. If you forget await, you get a coroutine object back, not the result!
🌐 httpx — Async HTTP Client LLM API Calls

🔷 Why httpx instead of requests?

requests is synchronous (blocking). httpx supports both sync and async, making it the go-to for LLM applications. Install: pip install httpx

🔷 Async GET and POST requests

import httpx
import asyncio

async def call_llm_api(prompt: str) -> dict:
    url = "https://api.openai.com/v1/chat/completions"
    headers = {
        "Authorization": f"Bearer {YOUR_API_KEY}",
        "Content-Type": "application/json"
    }
    payload = {
        "model": "gpt-4o",
        "messages": [{"role": "user", "content": prompt}]
    }

    # async with = async context manager (auto-closes client)
    async with httpx.AsyncClient() as client:
        response = await client.post(url, json=payload, headers=headers)
        response.raise_for_status()   # raise exception on 4xx/5xx
        return response.json()        # returns Python dict

async def main():
    result = await call_llm_api("What is the meaning of life?")
    print(result["choices"][0]["message"]["content"])

asyncio.run(main())

🔷 Batch API Calls (Concurrent)

async def batch_calls(prompts: list[str]) -> list[dict]:
    async with httpx.AsyncClient(timeout=30.0) as client:
        # Build all tasks first
        tasks = [
            client.post(
                "https://api.openai.com/v1/chat/completions",
                json={"model": "gpt-4o", "messages": [{"role": "user", "content": p}]},
                headers={"Authorization": f"Bearer {KEY}"}
            )
            for p in prompts
        ]
        # Fire all at once
        responses = await asyncio.gather(*tasks)
        return [r.json() for r in responses]
🎯 Interview Q

Q: What's the difference between async and threading?
A: Both allow concurrency but differently. Async is single-threaded — it switches between tasks when one is waiting for I/O. Threading uses multiple OS threads. For I/O-bound tasks (API calls), async is lighter and more efficient. For CPU-bound work, use multiprocessing.

APIs — FastAPI & Pydantic

🛡️ Pydantic Models — First! Validation

🔷 What is Pydantic?

Pydantic validates data using Python type hints. It's the backbone of FastAPI. Install: pip install pydantic

from pydantic import BaseModel, Field, field_validator
from typing import Optional

# Define a model by inheriting from BaseModel
class Message(BaseModel):
    role: str
    content: str

class ChatRequest(BaseModel):
    model: str = "gpt-4o"
    messages: list[Message]
    temperature: float = Field(default=0.7, ge=0.0, le=2.0)  # 0≤temp≤2
    max_tokens: Optional[int] = None
    stream: bool = False

    # Custom validator
    @field_validator("model")
    @classmethod
    def model_must_be_valid(cls, v):
        allowed = ["gpt-4o", "gpt-3.5-turbo"]
        if v not in allowed:
            raise ValueError(f"Model must be one of {allowed}")
        return v

# ── Using it
req = ChatRequest(
    messages=[Message(role="user", content="Hello")]
)
print(req.model)       # "gpt-4o"
print(req.temperature) # 0.7

# Convert to dict / JSON
print(req.model_dump())         # Python dict
print(req.model_dump_json())    # JSON string

# Parse from dict (e.g., incoming JSON)
data = {"messages": [{"role": "user", "content": "hi"}]}
req2 = ChatRequest.model_validate(data)
💡 Key Difference Dataclass: no validation at runtime. Pydantic: validates types and constraints automatically, raises clear errors.

🔷 POST Endpoint with Pydantic (Real LLM Wrapper)

from fastapi import FastAPI, HTTPException
from pydantic import BaseModel
from typing import Optional
import httpx

app = FastAPI()

# ── Request model
class ChatRequest(BaseModel):
    prompt: str
    model: str = "gpt-4o"
    temperature: float = 0.7

# ── Response model
class ChatResponse(BaseModel):
    answer: str
    model_used: str
    tokens: int

# ── POST endpoint
@app.post("/chat", response_model=ChatResponse)
async def chat(request: ChatRequest):
    try:
        async with httpx.AsyncClient() as client:
            resp = await client.post(
                "https://api.openai.com/v1/chat/completions",
                json={
                    "model": request.model,
                    "temperature": request.temperature,
                    "messages": [{"role": "user", "content": request.prompt}]
                },
                headers={"Authorization": "Bearer sk-..."},
                timeout=30.0
            )
            resp.raise_for_status()
            data = resp.json()

        return ChatResponse(
            answer=data["choices"][0]["message"]["content"],
            model_used=data["model"],
            tokens=data["usage"]["total_tokens"]
        )

    except httpx.HTTPStatusError as e:
        raise HTTPException(status_code=502, detail=f"LLM API error: {e}")
    except Exception as e:
        raise HTTPException(status_code=500, detail=f"Internal error: {e}")


# Path parameters
@app.get("/models/{model_id}")
def get_model(model_id: str):
    return {"model": model_id}

# Query parameters  → /search?q=hello&limit=5
@app.get("/search")
def search(q: str, limit: int = 10):
    return {"query": q, "limit": limit}

🔷 FastAPI Request Flow

Client sends JSON  →  FastAPI receives it
        ↓
Pydantic validates & parses into ChatRequest object
        ↓
Your async handler function runs
        ↓
You return a dict or Pydantic model
        ↓
FastAPI serializes it back to JSON  →  Client gets response
🎯 Interview Q

Q: How does FastAPI handle request validation?
A: FastAPI uses Pydantic under the hood. When you declare a parameter with a Pydantic model type, FastAPI automatically parses the request body and validates it. If validation fails, it returns a 422 Unprocessable Entity response with clear error details — no extra code needed.

🎯 Interview Q

Q: What's the difference between a path param and a query param in FastAPI?
A: Path param is part of the URL: /users/{user_id}. Query param is after the ?: /users?role=admin. In FastAPI, path params are declared in the route string, query params are just function parameters without a default or declared as Query().

🔷 Why venv?

Imagine two projects: one needs fastapi==0.95 and another needs fastapi==0.115. Without venv, they'd conflict. A virtual environment isolates each project's dependencies.

🎯 Interview Q

Q: Why should we use a virtual environment?
A: To isolate project dependencies. Without it, all projects share the same Python packages, causing version conflicts. venv gives each project its own package sandbox. It's standard practice for all Python projects.

🎯 Interview Q

Q: What's the difference between pip freeze and pip list?
A: pip list shows packages in a human-readable table. pip freeze outputs them in name==version format — exactly what goes into requirements.txt for reproducible installations.
