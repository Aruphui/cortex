🔌 Part 1 — Model Context Protocol (MCP)

1.1 What Is MCP & Why Does It Exist?

Model Context Protocol (MCP) is an open standard introduced by Anthropic (late 2024) that defines a universal, vendor-neutral interface between AI assistants / LLMs and external tools, data sources, and services.

📌 Core Idea Think of MCP as USB-C for AI. Just as USB-C lets you plug any device into any port without worrying about adapters, MCP lets any AI model connect to any tool without writing custom glue code for each pair.

The Problem Before MCP

Before MCP every AI product had to build N×M integrations:

Claude ──┬──> custom Slack plugin ├──> custom GitHub plugin └──> custom DB plugin GPT-4 ──┬──> different Slack plugin ├──> different GitHub plugin └──> different DB plugin

The Solution — MCP

Any LLM / Agent │ │ MCP Protocol (JSON-RPC 2.0) │ ┌────┴────────────────────────────────┐ │ MCP Server Layer │ ├──────────┬──────────┬───────────────┤ │ Slack │ GitHub │ Database │ │ Server │ Server │ Server │ └──────────┴──────────┴───────────────┘

Now you write one MCP server per tool and every MCP-aware AI model can use it.

1.2 Key Terminology

TermMeaning
MCP HostThe AI application that wants to use capabilities (Claude Desktop, your custom agent app)
MCP ClientThe component inside the host that speaks the MCP protocol
MCP ServerA lightweight process that exposes tools, resources, and prompts via MCP
TransportHow host ↔ server communicate (stdio, SSE, WebSocket, HTTP Streamable)

1.3 MCP Architecture Deep-Dive

╔══════════════════════════════════════════════════════╗ ║ MCP HOST (your app) ║ ║ ║ ║ ┌─────────────┐ ┌─────────────────────────┐ ║ ║ │ LLM │◄─────►│ MCP Client │ ║ ║ │ (Claude, │ │ - Connection Manager │ ║ ║ │ GPT, etc) │ │ - Capability Registry │ ║ ║ └─────────────┘ │ - Request Router │ ║ ║ └──────────┬──────────────┘ ║ ╚════════════════════════════════════╪════════════════╝ │ Transport ┌──────────────────┼──────────────────┐ │ │ │ ┌────────▼──────┐ ┌────────▼──────┐ ┌────────▼──────┐ │ MCP Server A │ │ MCP Server B │ │ MCP Server C │ │ (File System)│ │ (Database) │ │ (Web Search) │ └───────────────┘ └───────────────┘ └───────────────┘

Message Flow (Request/Response)

1
Initialization — Client sends initialize request with client info and supported protocol version
2
Capability Negotiation — Server responds with its capabilities (tools, resources, prompts it supports)
3
Tool Discovery — Client calls tools/list to enumerate available tools
4
LLM Decides — The AI model picks a tool based on user query
5
Tool Call — Client sends tools/call with arguments to the server
6
Result Injection — Server returns result → injected back into LLM context

1.4 The Three MCP Primitives

🔧

Tools

Functions the LLM can call to perform actions or retrieve data. The AI decides when and how to call them.

Example: search_web(query), create_file(name, content)

📁

Resources

Read-only data blobs the LLM can read — like files, DB rows, config. Identified by URI.

Example: file:///docs/readme.md, db://users/42

💬

Prompts

Reusable prompt templates that can be injected into the conversation with dynamic parameters.

Example: A "code-review" prompt template

Tools vs Resources — When to Use Each

ScenarioUse
Execute an action (send email, create ticket)Tool
Read a large document or fileResource
Query a database for a recordTool (or Resource if static)
Provide reusable system instructionsPrompt
Stream live dataResource (with subscriptions)

1.5 Transport Layers

TransportBest ForNotes
stdio Local tools, CLI integrations Server launched as a subprocess; communication via stdin/stdout. Simplest to implement.
HTTP + SSE Remote servers, cloud-hosted tools Client → Server via HTTP POST; Server → Client via Server-Sent Events. Most common for web.
HTTP Streamable Modern production (MCP 2025-03) Single HTTP endpoint with streaming. Replaces old SSE transport. Best for FastAPI.
WebSocket Bidirectional real-time Full-duplex; useful for streaming tool results or progress updates.

Minimal MCP Server (stdio)

from mcp.server import Server
from mcp.server.stdio import stdio_server
from mcp import types

# 1. Create the server instance
app = Server("my-first-mcp-server")

# 2. Register a tool — use the @app.list_tools decorator
@app.list_tools()
async def list_tools() -> list[types.Tool]:
    return [
        types.Tool(
            name="add_numbers",
            description="Add two numbers together",
            inputSchema={
                "type": "object",
                "properties": {
                    "a": {"type": "number", "description": "First number"},
                    "b": {"type": "number", "description": "Second number"},
                },
                "required": ["a", "b"],
            },
        )
    ]

# 3. Handle tool calls
@app.call_tool()
async def call_tool(
    name: str, arguments: dict
) -> list[types.TextContent]:
    if name == "add_numbers":
        result = arguments["a"] + arguments["b"]
        return [types.TextContent(type="text", text=str(result))]
    raise ValueError(f"Unknown tool: {name}")

# 4. Run the server
async def main():
    async with stdio_server() as (read_stream, write_stream):
        await app.run(read_stream, write_stream, app.create_initialization_options())

if __name__ == "__main__":
    import asyncio
    asyncio.run(main())

1.7 Building MCP Clients

A client connects to one or more MCP servers, discovers their capabilities, and routes LLM requests to the right tool.

from mcp import ClientSession, StdioServerParameters
from mcp.client.stdio import stdio_client

async def run_client():
    server_params = StdioServerParameters(
        command="python",
        args=["my_mcp_server.py"],
    )

    async with stdio_client(server_params) as (read, write):
        async with ClientSession(read, write) as session:

            # Initialize the connection
            await session.initialize()

            # List available tools
            tools = await session.list_tools()
            for tool in tools.tools:
                print(f"Tool: {tool.name} — {tool.description}")

            # Call a specific tool
            result = await session.call_tool(
                "add_numbers",
                arguments={"a": 10, "b": 32}
            )
            print(f"Result: {result.content[0].text}")  # 42

Multi-Server Client Pattern

import asyncio
from mcp import ClientSession
from mcp.client.http import http_client

class AgentMCPClient:
    """Manages connections to multiple MCP servers."""

    def __init__(self):
        self.sessions: dict[str, ClientSession] = {}
        self.all_tools: dict[str, str] = {}  # tool_name → server_name

    async def connect(self, server_name: str, url: str):
        read, write = await http_client(url).__aenter__()
        session = ClientSession(read, write)
        await session.initialize()
        self.sessions[server_name] = session

        # Index tools from this server
        tools = await session.list_tools()
        for tool in tools.tools:
            self.all_tools[tool.name] = server_name

    async def call_tool(self, tool_name: str, arguments: dict):
        server_name = self.all_tools[tool_name]
        session = self.sessions[server_name]
        return await session.call_tool(tool_name, arguments)

1.8 MCP Security Best Practices

⚠️ Critical MCP servers execute real actions. A compromised or malicious MCP server can cause your AI to delete files, leak secrets, or send unauthorized requests. Always apply principle of least privilege.
RiskMitigation
Tool injection via user inputValidate and sanitize all arguments; use strict JSON Schema
Unauthorized server connectionsWhitelist allowed MCP server URLs; validate server certificates
Sensitive data in tool resultsRedact secrets before returning; never return API keys in text
Prompt injection via resourcesTreat all resource content as untrusted; use content sandboxing
Excessive permissionsEach MCP server should only expose exactly the tools it needs
No auth on HTTP serversUse Bearer token / OAuth 2.0 on all remote MCP endpoints

Adding Auth to an MCP HTTP Server

from mcp.server.streamable_http import streamable_http_server
from starlette.middleware.base import BaseHTTPMiddleware
from starlette.requests import Request
from starlette.responses import JSONResponse

class BearerAuthMiddleware(BaseHTTPMiddleware):
    def __init__(self, app, token: str):
        super().__init__(app)
        self.token = token

    async def dispatch(self, request: Request, call_next):
        auth = request.headers.get("Authorization", "")
        if not auth.startswith("Bearer ") or auth[7:] != self.token:
            return JSONResponse({"error": "Unauthorized"}, status_code=401)
        return await call_next(request)

mcp_asgi = streamable_http_server(app)

# Wrap with auth middleware
from starlette.applications import Starlette
secure_app = Starlette()
secure_app.add_middleware(BearerAuthMiddleware, token="super-secret-token")
secure_app.mount("/", mcp_asgi)

2.1 What Is FastAPI?

FastAPI is a modern, high-performance Python web framework for building APIs, built on top of Starlette (ASGI) and Pydantic (data validation). It is the de-facto standard for serving AI/ML models and agent backends.

🚀

Speed

On par with NodeJS and Go for async I/O. One of the fastest Python frameworks.

🔍

Auto Docs

Swagger UI + ReDoc generated automatically from your code. Zero extra config.

🛡️

Type Safety

Pydantic validates all inputs/outputs. Catch bugs at request time, not runtime.

🔄

Async Native

Built for async/await. Perfect for LLM API calls, streaming, concurrency.

2.4 Pydantic Models — The Heart of FastAPI

Pydantic models define the shape of your request bodies, responses, and config. They provide automatic validation, serialisation, and documentation.

from pydantic import BaseModel, Field, field_validator
from typing import Optional, Literal
from datetime import datetime
from enum import Enum

class AgentStatus(str, Enum):
    idle      = "idle"
    running   = "running"
    completed = "completed"
    failed    = "failed"

class ToolConfig(BaseModel):
    name: str = Field(..., description="Tool identifier")
    enabled: bool = Field(True)
    timeout_seconds: int = Field(30, ge=1, le=300)

class AgentCreateRequest(BaseModel):
    name: str = Field(..., min_length=1, max_length=100, examples=["ResearchAgent"])
    model: str = Field("gpt-4o", description="LLM model to use")
    system_prompt: Optional[str] = None
    tools: list[ToolConfig] = Field(default_factory=list)
    max_iterations: int = Field(10, ge=1, le=100)

    @field_validator("name")
    @classmethod
    def name_must_not_contain_spaces(cls, v: str) -> str:
        if " " in v:
            raise ValueError("Agent name must not contain spaces")
        return v

class AgentResponse(BaseModel):
    id: int
    name: str
    status: AgentStatus
    created_at: datetime
    model: str

    model_config = {"from_attributes": True}  # Pydantic v2

# ── Using in Endpoints ────────────────────────────
from fastapi import FastAPI
app = FastAPI()

@app.post("/agents", response_model=AgentResponse, status_code=201)
async def create_agent(body: AgentCreateRequest):
    # body is fully validated before reaching here
    agent = {
        "id": 1,
        "name": body.name,
        "status": AgentStatus.idle,
        "created_at": datetime.utcnow(),
        "model": body.model,
    }
    return agent
python
💡 Response Models Always specify response_model=. This strips any extra internal fields (like passwords or API keys) before sending the response. Security by default!

2.5 Async & Concurrency — Critical for AI APIs

LLM calls can take 5–60+ seconds. Without async, one slow request blocks your entire server. FastAPI is fully async-first.

import asyncio
import httpx
from fastapi import FastAPI
from openai import AsyncOpenAI

app = FastAPI()
openai_client = AsyncOpenAI()  # Always use async client with FastAPI

# ── Async endpoint calling an LLM ────────────────
@app.post("/chat")
async def chat(message: str):
    # This does NOT block other requests
    response = await openai_client.chat.completions.create(
        model="gpt-4o",
        messages=[{"role": "user", "content": message}]
    )
    return {"reply": response.choices[0].message.content}

# ── Running multiple LLM calls concurrently ───────
@app.post("/multi-agent")
async def multi_agent(task: str):
    # Kick off 3 LLM calls at the same time
    results = await asyncio.gather(
        openai_client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"Research: {task}"}]
        ),
        openai_client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"Summarize: {task}"}]
        ),
        openai_client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": f"Critique: {task}"}]
        ),
    )
    return {
        "research":  results[0].choices[0].message.content,
        "summary":   results[1].choices[0].message.content,
        "critique":  results[2].choices[0].message.content,
    }

# ── When you MUST use sync code (e.g. blocking DB) ─
from fastapi.concurrency import run_in_threadpool

@app.get("/sync-work")
async def sync_work():
    # run_in_threadpool prevents blocking the event loop
    result = await run_in_threadpool(some_blocking_function, arg1, arg2)
    return {"result": result}

2.6 Dependency Injection — The DI System

FastAPI's DI system lets you declare reusable logic (DB connections, auth checks, config) that gets injected into any endpoint automatically.

from fastapi import FastAPI, Depends, HTTPException, status
from functools import lru_cache
from pydantic_settings import BaseSettings

# ── Settings via Pydantic ─────────────────────────
class Settings(BaseSettings):
    openai_api_key: str
    database_url: str
    secret_key: str

    class Config:
        env_file = ".env"

@lru_cache()  # Only create settings once
def get_settings() -> Settings:
    return Settings()

# ── DB Session Dependency ─────────────────────────
from sqlalchemy.ext.asyncio import AsyncSession, create_async_engine
from sqlalchemy.orm import sessionmaker

engine = create_async_engine("sqlite+aiosqlite:///./agents.db")
AsyncSessionLocal = sessionmaker(engine, class_=AsyncSession, expire_on_commit=False)

async def get_db() -> AsyncSession:  # This is a dependency
    async with AsyncSessionLocal() as session:
        try:
            yield session  # Yield gives session to endpoint
            await session.commit()
        except Exception:
            await session.rollback()
            raise

# ── Auth Dependency ───────────────────────────────
from fastapi.security import HTTPBearer, HTTPAuthorizationCredentials
import jwt

security = HTTPBearer()

async def get_current_user(
    credentials: HTTPAuthorizationCredentials = Depends(security),
    settings: Settings = Depends(get_settings),
) -> dict:
    try:
        payload = jwt.decode(credentials.credentials, settings.secret_key, algorithms=["HS256"])
        return payload
    except jwt.ExpiredSignatureError:
        raise HTTPException(status_code=401, detail="Token expired")
    except jwt.InvalidTokenError:
        raise HTTPException(status_code=401, detail="Invalid token")

# ── Using Dependencies in Endpoints ──────────────
app = FastAPI()

@app.get("/me")
async def get_me(current_user: dict = Depends(get_current_user)):
    return {"user": current_user}

@app.get("/agents")
async def get_agents(
    db: AsyncSession = Depends(get_db),
    current_user: dict = Depends(get_current_user),
    settings: Settings = Depends(get_settings),
):
    # db, user, and settings are all injected automatically
    return {"user": current_user["sub"], "db_url": settings.database_url}

@app.middleware("http")
async def log_requests(request: Request, call_next):
    request_id = str(uuid.uuid4())[:8]
    start_time = time.time()

    # Add request ID to headers for tracing
    request.state.request_id = request_id

    response = await call_next(request)

    process_time = (time.time() - start_time) * 1000
    print(f"[{request_id}] {request.method} {request.url.path} "
          f"→ {response.status_code} ({process_time:.1f}ms)")

    response.headers["X-Request-ID"] = request_id
    response.headers["X-Process-Time"] = f"{process_time:.1f}ms"
    return response

2.8 Auth — JWT + OAuth2

from fastapi import FastAPI, Depends, HTTPException
from fastapi.security import OAuth2PasswordBearer, OAuth2PasswordRequestForm
from pydantic import BaseModel
from datetime import datetime, timedelta
import jwt
import bcrypt

SECRET_KEY = "your-256-bit-secret"
ALGORITHM  = "HS256"
ACCESS_TOKEN_EXPIRE_MINUTES = 30

app = FastAPI()
oauth2_scheme = OAuth2PasswordBearer(tokenUrl="token")

# Fake user DB for demo
USERS_DB = {
    "alice": {
        "username": "alice",
        "hashed_password": bcrypt.hashpw(b"password123", bcrypt.gensalt()).decode(),
    }
}

class Token(BaseModel):
    access_token: str
    token_type: str

def create_access_token(data: dict, expires_delta: timedelta | None = None) -> str:
    to_encode = data.copy()
    expire = datetime.utcnow() + (expires_delta or timedelta(minutes=15))
    to_encode.update({"exp": expire})
    return jwt.encode(to_encode, SECRET_KEY, algorithm=ALGORITHM)

async def get_current_user(token: str = Depends(oauth2_scheme)) -> dict:
    try:
        payload = jwt.decode(token, SECRET_KEY, algorithms=[ALGORITHM])
        username: str = payload.get("sub")
        if username is None:
            raise HTTPException(status_code=401)
        return {"username": username}
    except jwt.PyJWTError:
        raise HTTPException(status_code=401, detail="Could not validate credentials")

@app.post("/token", response_model=Token)
async def login(form_data: OAuth2PasswordRequestForm = Depends()):
    user = USERS_DB.get(form_data.username)
    if not user or not bcrypt.checkpw(form_data.password.encode(), user["hashed_password"].encode()):
        raise HTTPException(status_code=400, detail="Incorrect username or password")

    access_token = create_access_token(
        data={"sub": form_data.username},
        expires_delta=timedelta(minutes=ACCESS_TOKEN_EXPIRE_MINUTES)
    )
    return Token(access_token=access_token, token_type="bearer")

@app.get("/protected")
async def protected_route(current_user: dict = Depends(get_current_user)):
    return {"message": f"Hello, {current_user['username']}!"}

2.9 WebSockets & Server-Sent Events (SSE) — LLM Streaming

When using LLMs, you want to stream tokens as they arrive rather than waiting for the full response. FastAPI handles both WebSockets and SSE perfectly.

Streaming LLM Response via SSE

from fastapi import FastAPI
from fastapi.responses import StreamingResponse
from openai import AsyncOpenAI
import asyncio

app = FastAPI()
client = AsyncOpenAI()

@app.post("/stream-chat")
async def stream_chat(message: str):

    async def generate():
        stream = await client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": message}],
            stream=True,  # Enable streaming
        )
        async for chunk in stream:
            delta = chunk.choices[0].delta.content
            if delta:
                # SSE format: data: \n\n
                yield f"data: {delta}\n\n"

        yield "data: [DONE]\n\n"  # Signal end of stream

    return StreamingResponse(
        generate(),
        media_type="text/event-stream",
        headers={
            "Cache-Control": "no-cache",
            "X-Accel-Buffering": "no",  # Disable Nginx buffering
        }
    )

WebSocket for Bidirectional Agent Chat

from fastapi import FastAPI, WebSocket, WebSocketDisconnect
from typing import dict, Any
import json

app = FastAPI()

class AgentWebSocketManager:
    def __init__(self):
        self.active_connections: list[WebSocket] = []

    async def connect(self, websocket: WebSocket):
        await websocket.accept()
        self.active_connections.append(websocket)

    def disconnect(self, websocket: WebSocket):
        self.active_connections.remove(websocket)

    async def send_message(self, websocket: WebSocket, data: dict):
        await websocket.send_json(data)

manager = AgentWebSocketManager()

@app.websocket("/ws/agent/{session_id}")
async def websocket_agent(websocket: WebSocket, session_id: str):
    await manager.connect(websocket)
    try:
        while True:
            # Wait for user message
            data = await websocket.receive_json()

3.1 What Is an AI Agent?

An AI Agent is a system where an LLM autonomously decides what actions to take, executes them, observes results, and loops until a goal is achieved — without human intervention for each step.

3.2 Tool Calling — The Core Mechanism

async def execute_tool(name: str, arguments: dict) -> str:

        return await search_web(**arguments)
    elif name == "read_file":
        return await read_file(**arguments)
    return f"Unknown tool: {name}"

# 4. The agent loop
async def run_agent(user_goal: str) -> str:
    messages = [{"role": "user", "content": user_goal}]

    while True:
        response = await client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=tools,
            tool_choice="auto",  # Let model decide
        )
        message = response.choices[0].message

        # Check if the model wants to call tools
        if message.tool_calls:
            # Add assistant's response to history
            messages.append(message)

            # Execute each requested tool call
            for tool_call in message.tool_calls:
                args = json.loads(tool_call.function.arguments)
                result = await execute_tool(tool_call.function.name, args)

                # Add tool result to messages
                messages.append({
                    "role": "tool",
                    "tool_call_id": tool_call.id,
                    "content": result,
                })

            # Loop back — model will process results
            continue

        # No tool calls — model has the final answer
        return message.content

3.3 Agent Memory Patterns

🧾

In-Context (Short-term)

The conversation messages list. Limited by context window. Lost after session ends.

🗂️

External (Long-term)

Database, Redis, or vector store. Persists across sessions. Retrieved and injected into context.

🔍

Episodic (Semantic)

Vector embeddings of past interactions. Retrieve relevant memories by semantic similarity.

📋

Procedural

Stored plans, workflows, and learned behaviours. How to do X.

Implementing Conversation Memory with Redis

import json
import redis.asyncio as redis
from typing import Optional

class ConversationMemory:
    def __init__(self, redis_url: str = "redis://localhost"):
        self.redis = redis.from_url(redis_url)
        self.max_messages = 20     # Keep last N messages
        self.ttl_seconds = 3600   # Sessions expire in 1 hour

    async def get_history(self, session_id: str) -> list[dict]:
        key = f"chat:{session_id}"
        raw = await self.redis.get(key)
        if raw:
            return json.loads(raw)
        return []

    async def add_message(self, session_id: str, role: str, content: str):
        history = await self.get_history(session_id)
        history.append({"role": role, "content": content})
        # Keep only recent messages to avoid context overflow
        history = history[-self.max_messages:]

        key = f"chat:{session_id}"
        await self.redis.setex(key, self.ttl_seconds, json.dumps(history))

    async def clear(self, session_id: str):
        await self.redis.delete(f"chat:{session_id}")

# ── Vector Memory with Embeddings ─────────────────
from openai import AsyncOpenAI
import numpy as np

class VectorMemory:
    def __init__(self):
        self.client = AsyncOpenAI()
        self.memories: list[dict] = []  # In prod: use Pinecone/Weaviate/pgvector

    async def store(self, text: str, metadata: dict = {}):
        embedding = await self._embed(text)
        self.memories.append({
            "text": text,
            "embedding": embedding,
            "metadata": metadata,
        })

    async def recall(self, query: str, top_k: int = 3) -> list[str]:
        if not self.memories:
            return []
        query_embedding = await self._embed(query)
        # Compute cosine similarity
        scores = [
            np.dot(query_embedding, m["embedding"]) /
            (np.linalg.norm(query_embedding) * np.linalg.norm(m["embedding"]))
            for m in self.memories
        ]
        top_indices = np.argsort(scores)[-top_k:][::-1]
        return [self.memories[i]["text"] for i in top_indices]

    async def _embed(self, text: str) -> list[float]:
        response = await self.client.embeddings.create(
            model="text-embedding-3-small", input=text
        )
        return response.data[0].embedding

3.4 Multi-Agent Orchestration

from dataclasses import dataclass, field
from typing import Callable, Awaitable
from openai import AsyncOpenAI
import asyncio

client = AsyncOpenAI()

@dataclass
class Agent:
    name: str
    system_prompt: str
    tools: list[dict] = field(default_factory=list)
    model: str = "gpt-4o"

    async def run(self, task: str) -> str:
        messages = [
            {"role": "system", "content": self.system_prompt},
            {"role": "user",   "content": task},
        ]
        response = await client.chat.completions.create(
            model=self.model, messages=messages, tools=self.tools or None
        )
        return response.choices[0].message.content

# ── Supervisor Pattern ─────────────────────────────
class SupervisorOrchestrator:
    def __init__(self):
        self.supervisor = Agent(
            name="Supervisor",
            system_prompt="""You are an orchestrator. Given a task, decompose it 
            into subtasks and assign each to the right specialist agent.
            Available agents: Researcher, Writer, Critic, Coder""",
        )
        self.agents = {
            "Researcher": Agent("Researcher", "You are an expert researcher."),
            "Writer":     Agent("Writer",     "You are an expert technical writer."),
            "Critic":     Agent("Critic",     "You critically review content."),
            "Coder":      Agent("Coder",      "You write clean Python code."),
        }

    async def run(self, goal: str) -> dict:
        # 1. Supervisor creates a plan
        plan = await self.supervisor.run(
            f"Goal: {goal}\nCreate a JSON plan with steps and agent assignments."
        )

        # 2. Execute steps (parallel where possible)
        results = {}
        for agent_name, task in self._parse_plan(plan).items():
            if agent_name in self.agents:
                results[agent_name] = await self.agents[agent_name].run(task)

        return results

    def _parse_plan(self, plan: str) -> dict:
        # Simplified — in production parse structured JSON
        return {"Researcher": plan, "Writer": plan}

from fastapi import FastAPI, Depends, BackgroundTasks
from fastapi.responses import StreamingResponse
from contextlib import asynccontextmanager
from pydantic import BaseModel
from openai import AsyncOpenAI
from mcp import ClientSession
from mcp.client.http import http_client
import json, asyncio

# ── Pydantic Models ───────────────────────────────
class AgentRequest(BaseModel):
    session_id: str
    message: str
    stream: bool = False

class AgentResponse(BaseModel):
    session_id: str
    response: str
    tools_used: list[str] = []

# ── MCP Client Manager ────────────────────────────
class MCPToolRegistry:
    def __init__(self):
        self.sessions: dict[str, ClientSession] = {}
        self.tool_schemas: list[dict] = []   # OpenAI format
        self._tool_to_server: dict[str, str] = {}

    async def connect_server(self, name: str, url: str):
        read, write = await http_client(url).__aenter__()
        session = ClientSession(read, write)
        await session.initialize()
        self.sessions[name] = session

        tools_result = await session.list_tools()
        for tool in tools_result.tools:
            self._tool_to_server[tool.name] = name
            self.tool_schemas.append({
                "type": "function",
                "function": {
                    "name": tool.name,
                    "description": tool.description,
                    "parameters": tool.inputSchema,
                }
            })

    async def execute(self, tool_name: str, arguments: dict) -> str:
        server_name = self._tool_to_server[tool_name]
        session = self.sessions[server_name]
        result = await session.call_tool(tool_name, arguments)
        return result.content[0].text if result.content else ""

# ── App Lifespan ──────────────────────────────────
@asynccontextmanager
async def lifespan(app: FastAPI):
    registry = MCPToolRegistry()
    await registry.connect_server("filesystem", "http://localhost:8001")
    await registry.connect_server("search",     "http://localhost:8002")
    app.state.registry = registry
    app.state.llm_client = AsyncOpenAI()
    yield

app = FastAPI(title="AI Agent API", lifespan=lifespan)

# ── Dependency ────────────────────────────────────
async def get_registry(request) -> MCPToolRegistry:
    return request.app.state.registry

# ── Agent Execution Logic ─────────────────────────
async def run_agent_loop(
    message: str,
    registry: MCPToolRegistry,
    llm_client: AsyncOpenAI,
) -> tuple[str, list[str]]:

    messages = [{"role": "user", "content": message}]
    tools_used = []

    for _ in range(10):  # Max 10 iterations
        response = await llm_client.chat.completions.create(
            model="gpt-4o",
            messages=messages,
            tools=registry.tool_schemas or None,
            tool_choice="auto",
        )
        msg = response.choices[0].message

        if not msg.tool_calls:
            return msg.content, tools_used

        messages.append(msg)
        for tool_call in msg.tool_calls:
            tool_name = tool_call.function.name
            args = json.loads(tool_call.function.arguments)
            tools_used.append(tool_name)
            result = await registry.execute(tool_name, args)
            messages.append({
                "role": "tool",
                "tool_call_id": tool_call.id,
                "content": result,
            })

    return "Max iterations reached.", tools_used

# ── Endpoints ─────────────────────────────────────
from fastapi import Request

@app.post("/agent/run", response_model=AgentResponse)
async def run_agent(body: AgentRequest, request: Request):
    registry: MCPToolRegistry = request.app.state.registry
    llm_client: AsyncOpenAI  = request.app.state.llm_client

    response_text, tools_used = await run_agent_loop(
        body.message, registry, llm_client
    )
    return AgentResponse(
        session_id=body.session_id,
        response=response_text,
        tools_used=tools_used,

@app.post("/agent/stream")
async def stream_agent(body: AgentRequest, request: Request):
    llm_client: AsyncOpenAI = request.app.state.llm_client

    async def generate():
        stream = await llm_client.chat.completions.create(
            model="gpt-4o",
            messages=[{"role": "user", "content": body.message}],
            stream=True,
        )
        async for chunk in stream:
            if chunk.choices[0].delta.content:
                yield f"data: {chunk.choices[0].delta.content}\n\n"
        yield "data: [DONE]\n\n"

    return StreamingResponse(generate(), media_type="text/event-stream")
