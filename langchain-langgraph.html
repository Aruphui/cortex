Part I — Foundations Chapter 01

Gen AI & LLM Fundamentals

Before writing a single line of LangChain code, you must deeply understand what powers it — Large Language Models, Transformer architecture, and the Gen AI landscape.

1.1 What is Generative AI?

Generative AI refers to a class of artificial intelligence systems capable of generating new, original content — text, images, code, audio, video — by learning statistical patterns from vast training datasets. Unlike discriminative models that classify existing data, generative models learn the underlying data distribution and sample from it.

Key generative model families:

  • Large Language Models (LLMs) — Text-based generation (GPT-4, Claude, Llama, Mistral)
  • Diffusion Models — Image generation (Stable Diffusion, DALL·E 3)
  • GANs — Generative Adversarial Networks (older paradigm)
  • VAEs — Variational Autoencoders
  • Multimodal Models — GPT-4o, Gemini Ultra (text + image + audio)

1.2 Transformer Architecture

LLMs are built on the Transformer architecture, introduced in the 2017 paper "Attention Is All You Need" by Vaswani et al. Understanding this architecture is critical to working effectively with LLMs.

Transformer Architecture (Decoder-only for GPT-style)

Input Tokens → Tokenizer
↓
Token Embeddings + Positional Encoding
↓
× N Transformer Decoder Blocks:
Multi-Head Self-Attention → LayerNorm → FFN → LayerNorm
↓
Linear Projection → Softmax → Next Token Probability

Key Concepts

  • Tokenization — Text is split into sub-word tokens using algorithms like BPE (Byte Pair Encoding) or SentencePiece. GPT-4 uses ~100K token vocabulary.
  • Embeddings — Each token maps to a dense high-dimensional vector (e.g., 4096 dims for GPT-4).
  • Self-Attention — Each token attends to every other token via Q (Query), K (Key), V (Value) projections. Attention(Q,K,V) = softmax(QKᵀ/√d_k) · V
  • Multi-Head Attention — Multiple attention heads run in parallel, each learning different relationships.
  • Context Window — Maximum number of tokens the model can process at once (GPT-4 Turbo: 128K, GPT-4o: 128K).
  • Temperature — Controls randomness in sampling. 0 = deterministic, 1 = balanced, 2 = very random.
  • Top-p (nucleus) sampling — Restricts sampling to the top-p probability mass tokens.

1.4 Pre-training vs. Fine-tuning vs. In-Context Learning

  • Pre-training — Train on billions of tokens via next-token prediction (autoregressive) or masked language modeling. Extremely expensive (millions of GPU-hours).
  • Instruction Fine-tuning — Further train on instruction-response pairs to improve helpfulness. Examples: InstructGPT, RLHF (Reinforcement Learning from Human Feedback).
  • In-Context Learning (ICL) — Provide examples in the prompt (few-shot) to guide the model without changing weights. This is what we do in LangChain.
  • RAG — Dynamically augment context with retrieved external knowledge at inference time. No weight changes needed.
  • LoRA / QLoRA — Parameter-efficient fine-tuning by training low-rank adapter matrices. Available in Azure AI Studio.

Chapter 06

Prompt Engineering & Templates

Prompts are the primary interface to LLMs. Mastering prompt design and LangChain's template system dramatically improves output quality and reliability.

6.1 Prompt Engineering Principles

  • Be specific and explicit — Vague prompts produce vague outputs. State exactly what you want.
  • Assign a persona — "You are an expert financial analyst..." sets the model's behavior frame.
  • Provide context — The model only knows what's in its context window.
  • Use structured formatting — Ask for JSON, markdown tables, or numbered lists explicitly.
  • Chain-of-thought (CoT) — "Think step by step" dramatically improves reasoning accuracy.
  • Few-shot examples — Provide input-output examples to define the expected pattern.
  • Constrain the output — "Respond in maximum 3 bullet points."
  • Avoid negations — "Do not..." is less effective than "Always..." alternatives.

Text Splitters & Chunking Strategies

Chunking is one of the most impactful decisions in a RAG pipeline. The right strategy dramatically improves retrieval quality and LLM comprehension.

11.1 Why Chunk?

  • LLMs have finite context windows — you can't send a 500-page PDF in one call
  • Embeddings work best on focused, semantically coherent passages (not entire documents)
  • Smaller chunks improve retrieval precision; larger chunks improve recall and context
  • Optimal chunk size varies by use case: Q&A (256–512 tokens), summarization (1024–2048 tokens)

11.2 RecursiveCharacterTextSplitter (Recommended Default)

Embeddings with Azure OpenAI

Embeddings convert text into dense numerical vectors that capture semantic meaning. They are the mathematical foundation of all semantic search, RAG, and clustering workflows.

12.1 What Are Embeddings?

An embedding is a list of floating-point numbers (a vector) that represents the semantic meaning of a piece of text in a high-dimensional space. Similar texts produce vectors close to each other in this space.

"Azure OpenAI service"
→
Embedding Model
→
[0.023, -0.141, 0.087, ..., 0.312]
3072 dimensions (text-embedding-3-large)

Distance between vectors = semantic similarity. Cosine similarity is the standard metric: ranges from -1 (opposite) to 1 (identical).

12.3 Semantic Similarity — Manual Calculation

import numpy as np

def cosine_similarity(v1: list, v2: list) -> float:
    a, b = np.array(v1), np.array(v2)
    return np.dot(a, b) / (np.linalg.norm(a) * np.linalg.norm(b))

sentences = [
    "How do I use Azure OpenAI?",
    "What is the Azure OpenAI Service?",
    "What is the capital of France?"
]
vecs = embeddings.embed_documents(sentences)

# Similarity matrix
for i in range(len(sentences)):
    for j in range(len(sentences)):
        sim = cosine_similarity(vecs[i], vecs[j])
        print(f"[{i}] vs [{j}]: {sim:.4f}")
# [0] vs [1]: ~0.92 (very similar — both about Azure OpenAI)
# [0] vs [2]: ~0.35 (not similar — different topic)

Tools & Toolkits

Tools let LLMs interact with the external world — call APIs, run code, search the web, query databases. They are the "hands" of an AI agent. Mastering tool design is critical to building reliable, production-grade agents.

15.1 What is a Tool?

A Tool is a Python function that an LLM can decide to call when it needs external information or to perform an action. Every tool has four essential components:

  • name — The identifier the LLM uses to reference the tool (snake_case recommended)
  • description — Tells the LLM when and why to use the tool. This is the most important field — a poor description causes the LLM to misuse or ignore the tool.
  • args_schema — A Pydantic model that defines and validates the tool's input parameters
  • func / coroutine — The actual Python function that executes the tool's logic
LLM receives user message
↓
LLM decides: "I need to call a tool"
Outputs tool_name + JSON args
↓
LangChain executes the tool function
↓
Tool result injected as ToolMessage into context
↓
LLM reasons over tool result → final answer

15.2 Creating Tools with the @tool Decorator

The simplest way to create a tool — LangChain auto-extracts the name from the function name and the description from the docstring.

from langchain_core.tools import tool
from datetime import datetime
import requests
import math

@tool
def get_current_datetime() -> str:
    """Returns the current date and time in UTC.
    Use this tool whenever the user asks about the current time, date, day of week, or year."""
    return datetime.utcnow().strftime("%Y-%m-%d %H:%M:%S UTC")


@tool
def calculator(expression: str) -> str:
    """Safely evaluates a mathematical expression and returns the result.
    Use this for arithmetic, algebra, percentages, or any numerical computation.
    Input must be a valid Python math expression.
    Examples: '2 + 2', '(150 * 0.18)', 'math.sqrt(144)', 'pow(2, 10)'
    Do NOT use for unit conversions — use a separate tool for that."""
    try:
        # Restrict builtins for safety
        allowed_names = {"math": math, "pow": pow, "abs": abs, "round": round}
        result = eval(expression, {"__builtins__": {}}, allowed_names)
        return f"Result: {result}"
    except ZeroDivisionError:
        return "Error: Division by zero"
    except Exception as e:
        return f"Error evaluating expression '{expression}': {str(e)}"


@tool
def get_weather(city: str, country_code: str = "US") -> str:
    """Retrieves the current weather conditions for a given city.
    Use this when the user asks about weather, temperature, or climate in a location.
    Args:
        city: The name of the city (e.g. 'London', 'Tokyo', 'Seattle')
        country_code: ISO 3166-1 alpha-2 country code, defaults to 'US' (e.g. 'GB', 'JP', 'IN')

    try:
        url      = f"https://wttr.in/{city},{country_code}?format=3"
        response = requests.get(url, timeout=10)
        response.raise_for_status()
        return response.text.strip()
    except Exception as e:
        return f"Could not fetch weather for {city}: {str(e)}"

from langchain_core.tools import StructuredTool
from pydantic import BaseModel, Field
from typing import Optional, Literal

# ── Define input schema ──
class KnowledgeBaseSearchInput(BaseModel):
    query: str = Field(
        description="The natural language search query"
    )
    top_k: int = Field(
        default=5,
        ge=1,
        le=20,
        description="Number of results to return (1-20). Use 3 for quick lookups, 10 for comprehensive research."
    )
    source_filter: Optional[str] = Field(
        default=None,
        description="Filter results to a specific document source (e.g. 'hr-policy.pdf'). Leave None to search all sources."
    )
    search_type: Literal["semantic", "hybrid"] = Field(
        default="hybrid",
        description="Search strategy: 'semantic' for conceptual queries, 'hybrid' for keyword+semantic (default)."
    )

# ── Define the function ──
def search_knowledge_base(
    query: str,
    top_k: int = 5,
    source_filter: Optional[str] = None,
    search_type: str = "hybrid"
) -> str:
    search_kwargs = {"k": top_k}
    if source_filter:
        search_kwargs["filter"] = {"source": source_filter}

    if search_type == "hybrid":
        docs = vectorstore.similarity_search(query, **search_kwargs)
    else:
        docs = vectorstore.similarity_search(query, **search_kwargs)

    if not docs:
        return "No relevant documents found for this query."

    results = []
    for i, doc in enumerate(docs, 1):
        source = doc.metadata.get("source", "unknown")
        page   = doc.metadata.get("page", "N/A")
        results.append(f"[{i}] Source: {source} | Page: {page}\n{doc.page_content}")

    return "\n\n---\n\n".join(results)

# ── Register as a StructuredTool ──

    name="search_knowledge_base",

- Product documentation and technical specs

15.7 Manual Tool Execution Loop

Understanding the full tool call → execute → observe loop before using the higher-level agent abstractions:

from langchain_core.messages import HumanMessage, AIMessage, ToolMessage

# Build a map from tool name → tool object for quick lookup
tool_map = {t.name: t for t in tools}

def run_tool_loop(user_message: str, max_steps: int = 10) -> str:
    messages = [HumanMessage(content=user_message)]

    for step in range(max_steps):
        response: AIMessage = llm_with_tools.invoke(messages)
        messages.append(response)

        # No tool calls → LLM produced final answer
        if not response.tool_calls:
            return response.content

        # Execute every requested tool call
        for tc in response.tool_calls:
            print(f"  🔧 Calling tool: {tc['name']}({tc['args']})")
            tool_fn    = tool_map[tc["name"]]
            tool_result = tool_fn.invoke(tc["args"])
            print(f"  ✅ Result: {str(tool_result)[:120]}")

            # Add result back as a ToolMessage — LLM can now reason over it
            messages.append(ToolMessage(
                content=str(tool_result),
                tool_call_id=tc["id"]
            ))

    return "Max steps reached without final answer."

answer = run_tool_loop("What is today's date, and what is sqrt(1764)?")
print("\nFinal Answer:", answer)

15.8 ToolNode — Automatic Tool Execution in LangGraph

ToolNode is a prebuilt LangGraph node that automatically executes all tool calls in the last AIMessage and appends ToolMessage results to state — no manual loop needed.

from langgraph.prebuilt import ToolNode
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated, Literal
from langgraph.graph.message import add_messages

class ToolAgentState(TypedDict):
    messages: Annotated[list, add_messages]

# ── Prebuilt ToolNode handles all tool execution automatically ──
tool_node = ToolNode(tools)   # Pass list of tools

def agent_node(state: ToolAgentState) -> dict:
    response = llm_with_tools.invoke(state["messages"])
    return {"messages": [response]}

def should_use_tools(state: ToolAgentState) -> Literal["tools", "__end__"]:
    last = state["messages"][-1]
    if hasattr(last, "tool_calls") and last.tool_calls:
        return "tools"
    return "__end__"

graph = StateGraph(ToolAgentState)
graph.add_node("agent", agent_node)
graph.add_node("tools", tool_node)        # ← ToolNode plugs in as a regular node
graph.add_edge(START,   "agent")
graph.add_conditional_edges("agent", should_use_tools)
graph.add_edge("tools", "agent")           # After tool execution, return to agent
app = graph.compile()

result = app.invoke({
    "messages": [HumanMessage(content="What's the weather in Tokyo and what is 2^20?")]
})
print(result["messages"][-1].content)

Part III — LangGraph Chapter 17

LangGraph Fundamentals

LangGraph extends LangChain with a graph-based orchestration engine for building stateful, multi-actor, multi-step AI workflows with full control over the agent loop.

17.1 Why LangGraph?

Traditional agent frameworks (AgentExecutor) are rigid: one LLM → pick tool → call tool → repeat. Real-world AI applications need:

  • Cycles — loop back to previous steps based on new information
  • Branching — take different paths based on conditions
  • Parallel execution — run multiple agents/tools simultaneously
  • Human-in-the-loop — pause and wait for user approval
  • Persistence — resume from where the agent stopped (crashes, pauses)
  • Observability — inspect and debug every step of the workflow

LangGraph models your AI workflow as a directed graph (nodes + edges + state) — giving you full, explicit control.

17.2 Core Concepts

📦

State

A TypedDict that persists data as it flows through the graph. Every node reads from and writes to state.

⚙️

Nodes

Python functions or Runnables that receive state, perform logic (call LLM, run tool), and return state updates.

➡️

Edges

from typing import Annotated

# Custom reducer: keep only unique items
def add_unique(left: list, right: list) -> list:
    existing = {str(item) for item in left}

LangGraph's interrupt mechanism pauses graph execution mid-workflow to collect human input, approval, or correction — essential for high-stakes production agents.

21.1 Why HITL?

  • Approval gates — Agent wants to send an email or delete data → wait for human OK
  • Ambiguity resolution — Agent isn't sure which database to query → ask user
  • Quality review — Generated content needs human review before publishing
  • Safety — Stop dangerous or unexpected actions before execution

21.2 interrupt() — Pause Graph Mid-Node

from langgraph.graph import StateGraph, START, END
from langgraph.checkpoint.memory import MemorySaver
from langgraph.types import interrupt
from typing import TypedDict, Annotated
from langgraph.graph.message import add_messages
from langchain_core.messages import AIMessage

class ApprovalState(TypedDict):
    messages:    Annotated[list, add_messages]
    action_plan: str
    approved:    bool

def plan_node(state: ApprovalState) -> dict:
    plan = llm.invoke(state["messages"]).content
    return {"action_plan": plan}

def review_node(state: ApprovalState) -> dict:
    # PAUSE HERE — graph suspends; resumes when .invoke() is called again with Command(resume=...)
    human_decision = interrupt({
        "question":    "Do you approve this action plan?",
        "action_plan": state["action_plan"]

    return     {"messages": [AIMessage(content="❌ Action cancelled by user.")]}

graph.add_edge("plan",    "review")
graph.add_edge("review",  "execute")
graph.add_edge("execute", END)

from langchain_core.prompts import ChatPromptTemplate
from langchain_core.output_parsers import StrOutputParser
from langgraph.graph import StateGraph, START, END
from typing import TypedDict, Annotated, Literal
import operator

class SupervisorState(TypedDict):
    messages:     Annotated[list, add_messages]
    agent_outputs: Annotated[list, operator.add]
    next_agent:    str
    final_answer:  str

# ── Supervisor decides which agent to call ──
supervisor_prompt = ChatPromptTemplate.from_messages([
    ("system", """You are a supervisor managing three specialist agents:
- rag_agent: answers questions from internal documents
- code_agent: writes and explains code
- search_agent: searches the web for current information
- FINISH: when the task is complete

Based on the conversation, respond with ONLY the name of the next agent to call, or FINISH."""),
    ("human", "{messages}")
])

def supervisor_node(state: SupervisorState) -> dict:
    chain = supervisor_prompt | llm | StrOutputParser()
    decision = chain.invoke({"messages": state["messages"]}).strip()
    return {"next_agent": decision}

# ── Specialist Agents ──
def rag_agent_node(state: SupervisorState) -> dict:
    query = state["messages"][-1].content
    docs  = retriever.invoke(query)
    ctx   = "\n".join(d.page_content for d in docs)
    answer = llm.invoke(f"Answer based on context:\n{ctx}\n\nQuestion: {query}").content
    return {
        "messages":      [AIMessage(content=f"[RAG Agent]: {answer}")],
        "agent_outputs": [answer]
    }

def code_agent_node(state: SupervisorState) -> dict:
    query  = state["messages"][-1].content
    answer = llm.invoke(f"You are a Python expert. {query}").content
    return {
        "messages":      [AIMessage(content=f"[Code Agent]: {answer}")],
        "agent_outputs": [answer]
    }

def search_agent_node(state: SupervisorState) -> dict:
    query  = state["messages"][-1].content
    result = search_tool.invoke(query)
    answer = llm.invoke(f"Summarize this search result:\n{result}\n\nFor query: {query}").content
    return {
        "messages":      [AIMessage(content=f"[Search Agent]: {answer}")],
        "agent_outputs": [answer]
    }

def aggregate_node(state: SupervisorState) -> dict:
    outputs = "\n\n".join(state["agent_outputs"])
    final   = llm.invoke(f"Synthesize these agent outputs into a final answer:\n{outputs}").content
    return {"final_answer": final, "messages": [AIMessage(content=final)]}

# ── Router function ──
def route_to_agent(state: SupervisorState) -> Literal["rag_agent", "code_agent", "search_agent", "aggregate"]:
    mapping = {
        "rag_agent":    "rag_agent",
        "code_agent":   "code_agent",
        "search_agent": "search_agent",
        "FINISH":       "aggregate"
    }
    return mapping.get(state["next_agent"], "aggregate")

# ── Build Graph ──
graph = StateGraph(SupervisorState)
graph.add_node("supervisor",   supervisor_node)
graph.add_node("rag_agent",    rag_agent_node)
graph.add_node("code_agent",   code_agent_node)
graph.add_node("search_agent", search_agent_node)
graph.add_node("aggregate",    aggregate_node)
graph.add_edge(START, "supervisor")
graph.add_conditional_edges("supervisor", route_to_agent)
graph.add_edge("rag_agent",    "supervisor")
graph.add_edge("code_agent",   "supervisor")
graph.add_edge("search_agent", "supervisor")
graph.add_edge("aggregate",    END)
multi_agent_app = graph.compile()

Persistence & Checkpointers

Checkpointers give LangGraph graphs long-term memory, crash recovery, and time-travel debugging by saving state snapshots after every node execution.

23.1 How Checkpointing Works

Every time a node completes, LangGraph saves a state snapshot called a checkpoint to the backend store. Each checkpoint is identified by thread_id (conversation) and checkpoint_id (specific moment in time). This enables:

  • Resume after crash — re-invoke with the same thread_id to continue from last checkpoint
  • Time-travel debugging — replay from any prior checkpoint
  • Human-in-the-loop — state persists while waiting for human input
  • Multi-session memory — different threads = different users/conversations

26.3 RAG Fusion — Multi-Query + Reciprocal Rank Fusion

from langchain_core.runnables import RunnableLambda

def generate_queries(question: str) -> list[str]:
    prompt = ChatPromptTemplate.from_messages([
        ("system", "Generate 4 different search queries to find information for this question. Return as a JSON array."),
        ("human", "{question}")
    ])
    chain   = prompt | llm.with_structured_output({"type": "array", "items": {"type": "string"}})
    return chain.invoke({"question": question})

def reciprocal_rank_fusion(results_lists: list[list], k: int = 60) -> list:
    scores = {}
    for docs in results_lists:
        for rank, doc in enumerate(docs):
            key = doc.page_content
            scores[key] = scores.get(key, 0) + 1 / (k + rank + 1)
    sorted_docs = sorted(scores, key=scores.get, reverse=True)
    return sorted_docs[:5]

def rag_fusion_retriever(question: str) -> list:
    queries      = generate_queries(question)
    all_results  = [retriever.invoke(q) for q in queries]
    fused        = reciprocal_rank_fusion(all_results)
    return fused

def is_content_safe(text: str, threshold: int = 4) -> tuple[bool, str]:
    """Returns (is_safe, reason). Threshold: 0=safe,2=low,4=medium,6=high severity."""
    try:
        response = safety_client.analyze_text(AnalyzeTextOptions(text=text))

                return False, reason
        return True, "safe"

        return True, "bypass (api error)"  # fail-open or fail-closed per your policy

        return {"blocked": True, "block_reason": "Input too long (max 4000 chars)"}

    # 2. PII redaction
    clean_text, pii_found = redact_pii(text)
    if pii_found:
        state["messages"][-1] = HumanMessage(content=clean_text)

    # 3. Content safety check
    safe, reason = is_content_safe(clean_text)
    if not safe:
        return {"blocked": True, "block_reason": f"Content policy violation: {reason}"}

    return {"blocked": False, "block_reason": ""}

def output_guard_node(state: GuardedState) -> dict:
    response_text = state["messages"][-1].content
    safe, reason  = is_content_safe(response_text)
    if not safe:
        return {"messages": [AIMessage(
            content="I wasn't able to generate a safe response. Please rephrase your question."
        )]}
    return {}

def block_router(state: GuardedState) -> Literal["llm_node", "blocked_node"]:
    return "blocked_node" if state["blocked"] else "llm_node"

def blocked_node(state: GuardedState) -> dict:

        content=f"I'm sorry, I can't process that request. {state['block_reason']}"
    )]}

def llm_node(state: GuardedState) -> dict:
    system   = SystemMessage(content=HARDENED_SYSTEM_PROMPT)
    response = llm.invoke([system] + state["messages"])
    return {"messages": [response]}

from typing import TypedDict, Annotated, List, Optional
from langgraph.graph import StateGraph, START, END

from langchain_core.messages import HumanMessage, AIMessage, SystemMessage
from pydantic import BaseModel, Field

class RAGState(TypedDict):
    messages:      Annotated[list, add_messages]
    rewritten_query: str
    retrieved_docs:  List[dict]
    context:         str
    citations:       List[str]
    blocked:         bool

# ── Node 1: Input Guard ──
def input_guard(state: RAGState) -> dict:
    text         = state["messages"][-1].content
    safe, reason = is_content_safe(text)
    clean, _    = redact_pii(text)
    if not safe:
        return {"blocked": True}
    return {"blocked": False, "messages": [HumanMessage(content=clean)]}

# ── Node 2: Query Rewrite ──
def query_rewrite(state: RAGState) -> dict:
    history = state["messages"][:-1]
    current = state["messages"][-1].content
    rewrite_prompt = ChatPromptTemplate.from_messages([
        ("system", "Given the conversation history, rewrite the latest question as a standalone search query optimised for document retrieval. Return ONLY the rewritten query — nothing else."),
        ("human", "History: {history}\n\nLatest question: {question}")
    ])
    rewritten = (rewrite_prompt | llm | StrOutputParser()).invoke({
        "history":  "\n".join(m.content for m in history[-4:]),
        "question": current
    })
    return {"rewritten_query": rewritten}

# ── Node 3: Hybrid Retrieval ──
def retrieve(state: RAGState) -> dict:
    docs     = vectorstore.semantic_hybrid_search(state["rewritten_query"], k=5)
    doc_list = [
        {"content": d.page_content,
         "source":  d.metadata.get("source", "unknown"),
         "page":    d.metadata.get("page", "N/A")}
        for d in docs
    ]
    context = "\n\n".join(
        f"[Doc {i+1} | {d['source']} p.{d['page']}]\n{d['content']}"
        for i, d in enumerate(doc_list)
    )
    citations = [f"{d['source']} (page {d['page']})" for d in doc_list]
    return {"retrieved_docs": doc_list, "context": context, "citations": citations}

# ── Node 4: Generate ──
def generate(state: RAGState) -> dict:
    system = SystemMessage(content=f"""{HARDENED_SYSTEM_PROMPT}

Retrieved Context:
{state['context']}

Instructions:
- Answer ONLY from the context above.
- Cite sources as [Doc N] inline.
- If context is insufficient, say so clearly.""")
    response = llm.invoke([system] + state["messages"])
    answer   = response.content
    if state["citations"]:
        answer += "\n\n**Sources:** " + " | ".join(state["citations"])
    return {"messages": [AIMessage(content=answer)]}

# ── Build Graph ──
def route_after_guard(state: RAGState) -> str:
    return "blocked" if state["blocked"] else "query_rewrite"

rag_graph = StateGraph(RAGState)
rag_graph.add_node("input_guard",   input_guard)
rag_graph.add_node("query_rewrite", query_rewrite)
rag_graph.add_node("retrieve",      retrieve)
rag_graph.add_node("generate",      generate)
rag_graph.add_node("blocked",       lambda s: {"messages": [AIMessage(content="Request blocked by safety policy.")]})
rag_graph.add_edge(START,           "input_guard")
rag_graph.add_conditional_edges("input_guard", route_after_guard)
rag_graph.add_edge("query_rewrite", "retrieve")
rag_graph.add_edge("retrieve",      "generate")
rag_graph.add_edge("generate",      END)
rag_graph.add_edge("blocked",       END)

checkpointer = PostgresSaver.from_conn_string(get_secret("postgres-connection-string"))
rag_app      = rag_graph.compile(checkpointer=checkpointer)

        ("human",  "Topic: {topic}\n\nFindings:\n{findings}")

        "message":      "Please review the draft report.",

        ("system", "Revise the draft report based on the reviewer's feedback."),
        ("human",  "Draft:\n{draft}\n\nFeedback: {feedback}")
    ]) | llm | StrOutputParser()).invoke({
        "draft":    state["draft_report"],
        "feedback": feedback
    })

# ── Node 3: SQL Validation ──
def sql_validation_node(state: SQLAgentState) -> dict:
    sql  = state["generated_sql"].strip().upper()
    FORBIDDEN = [r"\bUPDATE\b", r"\bDELETE\b", r"\bINSERT\b",
                  r"\bDROP\b",   r"\bEXEC\b",   r"\bTRUNCATE\b",
                  r"\bCREATE\b", r"\bALTER\b",  r"\bXP_\w+"]
    for pat in FORBIDDEN:
        if re.search(pat, sql):
            return {"sql_valid": False, "sql_error": f"Forbidden SQL keyword detected: {pat}"}
    if not sql.startswith("SELECT"):
        return {"sql_valid": False, "sql_error": "Query must start with SELECT"}
    return {"sql_valid": True, "sql_error": ""}

# ── Node 4: SQL Execution ──
def sql_execution_node(state: SQLAgentState) -> dict:
    result = run_safe_sql_query.invoke({"query": state["generated_sql"]})
    if result.startswith("SQL_ERROR:"):
        return {"sql_valid": False, "sql_error": result, "raw_results": ""}
    return {"raw_results": result, "sql_error": ""}
